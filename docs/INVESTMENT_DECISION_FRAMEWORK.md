# NASDX 投资决策框架

## 目标

把多智能体研究结果转成可执行但可复核的行动计划，避免只给“看多/看空”标签。

## 输出字段

- 方向：偏多、谨慎偏多、偏空、震荡/证据不足。
- 动作：分批布局、轻仓试错、回避或减仓、观察等待。
- 仓位区间：按信号一致性和风险维度给出上限。
- 风险画像：保守、均衡、进取三档，影响仓位区间但不改变研究事实。
- 数据状态：行情过期、扫描覆盖率不足时自动降仓或要求刷新。
- 入场条件：趋势、资金流、板块强度和供应链卡点证据。
- 退出/止损：均线/前低、风险维度转弱、资金流转弱。
- 复核触发：财报、订单、客户验证、产能、融资、主题拥挤度。

## 组合级路线

`nasdx.portfolio` 把 ETF 扫描、60只个股扫描、深度分析报告和数据新鲜度合并成组合路线：

- 仓位框架：总仓位上限、ETF 主线预算、个股卫星预算、现金缓冲。
- 资金换算：把百分比仓位临时换算成总资金、ETF/个股预算、单票上限和第一笔试错金额。
- 候选分层：ETF 主线、个股卫星、观察名单、回避/减仓池。
- 未来情景：数据恢复后再判断、强势延续、信号转弱；数据正常时切换为顺势偏多、结构轮动、防守下行。
- 执行规则：先数据闸门、先 ETF 后个股、先分批后加仓、先退出再寻找新机会。
- 监控清单：每天收盘刷新路线，每周复核主题拥挤度，重大公告或外部冲击立即复核。
- 深度报告：过期报告只保留为重跑提醒，不参与当天候选排序。
- 扫描覆盖率：若有效数据低于池子 50%，该榜单只作为数据源异常提示，不进入加仓候选。
- 报告动作优先级：若深度报告动作是“回避或减仓”，即使最终信号偏多，也不能进入 ETF 主线或个股卫星试错池。

## 无 API 深度报告

`nasdx.rule_based_analysis` 在没有 LLM API Key 或本地模型时生成同结构深度报告：

- 输出仍是 `report_CODE_DATE.json/html`，网页、组合路线和最终简报不用改读取路径。
- 维度仍包含技术面、资金流、风险、板块、供应链瓶颈和综合判断。
- 供应链瓶颈只作为 Serenity 研究假设，公告、订单、客户、产能和财务映射仍必须人工复核。
- 规则版报告会写入 `analysis_mode=rules`，避免和 LLM 多智能体报告混淆。

## 研究阶段执行

`nasdx.environments.research` 默认并发运行技术面、资金流、风险、板块和供应链瓶颈 5 个 Agent，返回结果仍按固定维度顺序组织，便于后续 Battle 和 Synthesis 稳定消费。生产环境可通过 `NASDX_RESEARCH_MAX_WORKERS` 控制并发度；设置为 `1` 时退回顺序执行，用于调试或 API 限流。

每个 LLM Agent 都会追加统一结构化输出契约，优先解析 JSON 字段 `signal`、`confidence`、`conclusion`、`key_points`，再组装 `AnalysisResult`。如果模型没有返回合法 JSON，才回退到旧的 `【信号】/【置信度】` 文本尾标，避免格式漂移直接污染投资路线。

Streamlit、行情抓取和量化模块导入时不改写全局 `requests.get` 或代理环境变量；HTTP 连接策略留给 `requests` 原生环境代理、AkShare 数据源和 `nasdx.market_sources` 多源回退处理。

Streamlit 会话状态只保存可序列化的页面和任务标识。API Key、Base URL 和模型名不写回全局 `os.environ` 或 `nasdx.llm` 单例，而是在启动深度分析子进程时通过环境变量传入；后台任务用 `task_id` 关联线程和日志，线程对象不进入 `session_state`，同一股票的并发日志也不会互相覆盖。

## 最终投资简报

`nasdx.investment_brief` 把组合路线压缩成可读简报，供没有 LLM API Key 或只做盘后复盘时使用：

- 投资方向：当前姿态、主线 ETF、个股卫星和现金缓冲。
- 仓位动作：按风险画像给出总仓位、ETF 预算、个股预算和单票上限。
- 候选剧本：每个前排候选只给入场条件、失效条件、复核动作，不给无条件买入指令。
- 候选证据核查：`nasdx.candidate_audit` 为每个候选输出数据闸门、扫描排序、深度报告、风险红灯、公告/成交人工复核和仓位纪律；缺深度报告的候选会标记为“先补深度报告”，不作为试错候选。
- 资金仓位换算：`nasdx.position_sizing` 接收临时总资金和已有 ETF/个股/其他仓位，只在本次页面或 CLI 输出中换算剩余额度、候选上限和第一笔试错金额，不保存账户数据。
- 建议漂移追踪：`nasdx.recommendation_tracker` 对比最新简报和上一份不同时间简报，标出行动闸门、市场姿态、仓位框架、候选新增/移除/状态变化，以及下次复盘重点。
- 建议结果复盘：`nasdx.recommendation_review` 用最新行情、扫描榜单和当前简报状态复盘上一份建议，区分信号延续、降级复核、仍待补证据和缺当前数据。它不计算真实收益，真实收益需要成交价、持仓、费用和账户流水。
- 真实账户复盘：`nasdx.account_review` 只读取用户导入的成交 CSV，计算已实现盈亏、浮动盈亏、当前仓位和路线匹配；没有账户流水时返回缺失状态，不从研究建议倒推收益。
- 执行队列：`nasdx.execution_queue` 把候选证据核查翻译成盘前、盘中、盘后的动作。盘前主要确认数据闸门和补报告，盘中只做人工复核后的试错/观察/回避判断，盘后重新生成明日路线。
- 外部复核包：`nasdx.external_review` 为每个候选给出公告、行情和交易所入口，以及必须人工确认的通过条件。该层只提供复核入口和闸门，链接存在不代表复核已通过。
- 复盘快照包：`nasdx.review_snapshot` 把 latest 路线、最终简报、建议漂移追踪、建议结果复盘、候选审计、执行队列、外部复核包和来源文件哈希打包成 ZIP，方便盘后留档和回看建议演变。
- SQLite 历史库：`nasdx.history_store` 在保存报告、扫描、组合路线、最终简报和复盘产物时追加 `nasdx_history.db`，用于回看历史演变；原 Markdown/JSON 输出仍是主要交付文件。
- 未来情景：强势延续、结构轮动、防守下行等场景下的仓位处理。
- 数据证据：列出行情、ETF 扫描、个股扫描、深度报告的数据状态和来源文件。

## 纪律

LLM 或规则深度报告负责解释单票逻辑，`nasdx.decision` 负责单票动作和风险边界，`nasdx.portfolio` 负责组合级仓位和未来情景，`nasdx.position_sizing` 负责把路线百分比换算成临时账户金额边界，`nasdx.recommendation_tracker` 负责跨次简报变化追踪，`nasdx.recommendation_review` 负责用后续行情/扫描复盘上一份建议是否延续或降级，`nasdx.account_review` 负责用账户流水复盘真实持仓收益和路线匹配，`nasdx.candidate_audit` 负责候选级证据核查，`nasdx.execution_queue` 负责把审计结论转成执行队列，`nasdx.external_review` 负责外部复核入口和通过条件，`nasdx.review_snapshot` 负责复盘留档，`nasdx.history_store` 负责把历史产物追加到 `nasdx_history.db`，`nasdx.investment_brief` 负责把路线整理成最终研究简报。若风险维度偏空，仓位上限自动下调；若供应链卡点证据不足，行动计划会要求公告/财报核验；若 `nasdx.data_quality` 判断行情过期，或扫描覆盖率不足，行动计划会降仓或要求刷新后再执行；若候选状态较上次发生变化，先解释变化和复核原因，再决定是否升级试错；若没有成交价、持仓、费用和账户流水，不输出真实收益结论。

## 边界

该框架是研究辅助，不保证收益，也不能替代个人风险承受能力评估、最新公告核验和真实交易前复盘。
